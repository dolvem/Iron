# MD3 Theming and Dynamic Color

Guide to creating, applying, and managing Material Design 3 themes in Jetpack Compose.

## Theme architecture

The semantic roles (primary, onSurface, surface containers, etc.) are the same everywhere;
in Compose the theme surface is `MaterialTheme(colorScheme, typography, shapes)`.

## Jetpack Compose theming

Use `androidx.compose.material3.MaterialTheme`. Iron runs on Android 12+ (minSdk 31), so
dynamic color is native on every device: no fallback palette to write or maintain, no
`Build.VERSION.SDK_INT` check (project rule). See `ui/theme/Theme.kt`.

```kotlin
@Composable
fun IronTheme(mode: ThemeMode = ThemeMode.SYSTEM, content: @Composable () -> Unit) {
    val context = LocalContext.current

    val darkTheme = when (mode) {
        ThemeMode.DARK -> true
        ThemeMode.LIGHT -> false
        ThemeMode.SYSTEM -> isSystemInDarkTheme()
    }

    // minSdk 31: dynamic color is native, no version check (project rule)
    val colorScheme = if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)

    MaterialTheme(colorScheme = colorScheme, content = content)
}
```

`LocalContext` here is legitimate: `dynamicLightColorScheme` / `dynamicDarkColorScheme`
require a `Context`. For strings and locale, use `LocalResources.current` and
`LocalLocale.current.platformLocale`, never `LocalContext` or `Locale.getDefault()` (D72).

For a static (non-dynamic) theme, use `lightColorScheme()` / `darkColorScheme()` or the
Kotlin code generated by [Material Theme Builder](https://material-foundation.github.io/material-theme-builder/).

## Brand color integration

### Mapping existing brand colors

| Brand concept | MD3 role |
|--------------|----------|
| Primary brand color | Use as seed for the `primary` palette |
| Secondary brand color | Override `secondary` or use as custom color |
| Accent color | Map to `tertiary` |
| Alert/danger color | Override `error` (or keep MD3 default) |
| Background | Generated from seed (do not hardcode) |

The simplest approach: use the primary brand color as the seed. The algorithm generates
harmonious secondary and tertiary colors automatically.

### Color harmonization

To integrate a specific brand color that was not generated from the seed, harmonize it:
shift its hue slightly toward the scheme's primary so it feels cohesive without losing its
identity (`Blend.harmonize(customColorArgb, primaryColorArgb)` in
`material-color-utilities`, or bake it into the generated `Theme.kt`).

## Dark theme

Dark theme is generated automatically from the same seed color; the tonal mapping shifts:

- Light theme: lighter tones (80–100) for surfaces, darker tones (10–40) for accents
- Dark theme: darker tones (4–22) for surfaces, lighter tones (80–90) for accents

With dynamic color, light and dark schemes come from the system. Verify contrast with
dynamic color active (D35): 4.5:1 for normal text, 3:1 for large text and borders.

## High contrast themes

MD3 supports 3 contrast levels via the `contrast` parameter:

| Level | Value | Effect |
|-------|-------|--------|
| Standard | 0.0 | Default tonal distance |
| Medium | 0.5 | Increased tonal distance, easier to read |
| High | 1.0 | Maximum tonal distance, highest legibility |

Higher contrast increases the tonal distance between paired roles (e.g. `primary` and
`on-primary`), making text more legible without fundamentally changing the color feel. On
Android the user controls this through system accessibility settings; verify the app under
high contrast in emulator (D35).

## Component-level overrides

In Compose, override component appearance through defaults objects, not raw values:

```kotlin
Button(
    onClick = { /* ... */ },
    colors = ButtonDefaults.buttonColors(
        containerColor = MaterialTheme.colorScheme.tertiary,
        contentColor = MaterialTheme.colorScheme.onTertiary,
    ),
    shape = MaterialTheme.shapes.small,
) { Text("Custom") }
```

Available defaults: `ButtonDefaults`, `TextFieldDefaults`, `CardDefaults`,
`NavigationBarDefaults`, `DialogDefaults`, `SegmentedButtonDefaults`, etc. Always reference
`MaterialTheme.colorScheme` roles inside them — never raw `Color(0x…)` values.

## Scoped themes

A scoped theme is a nested `MaterialTheme` that overrides only what changes:

```kotlin
MaterialTheme(
    colorScheme = MaterialTheme.colorScheme.copy(
        primary = MaterialTheme.colorScheme.tertiary,
    ),
) {
    // Subtree uses the overridden roles
}
```

Components inside read the closest ancestor `MaterialTheme`, the same cascade idea as CSS
custom properties.

## Dynamic color from content

A seed color can be extracted from in-app content (album art, book cover) to create a
contextual scheme: quantize the image pixels, score them, pick the best seed, then build the
scheme with `material-color-utilities` or a generated scheme. This is app-specific, not
system wallpaper theming.
